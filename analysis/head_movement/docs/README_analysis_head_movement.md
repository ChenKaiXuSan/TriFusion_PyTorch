# 头部运动分析说明（STEP1：全走行区间）

版本：2026-11-27。对应数据目录 `data/drive/downstream_analysis/head_movement_analysis/`，
代码在 TriFusion 仓库 `analysis/head_movement/`（分支 `hybrid-fusion`）。

本文件说明这项分析做了什么、数据从哪里来、每个输出文件和每一列是什么意思、主要结果，以及使用时必须注意的地方。
表格都是 CSV（可直接用 Excel 打开），图是 PNG，阅读不需要编程知识。

---

## 0. 一页摘要

- **对象**：22 位受试者 × 4 种环境 = 88 段模拟驾驶，每段平均 5.7 分钟。
- **测的是什么**：驾驶者头部相对躯干的水平转动（左右，yaw）和俯仰（上下，pitch），由三台摄像头融合得到的 3D 关节点计算。
- **两套指标，不要混用**：
  - **算法检出的转头**（列名以 `ai_` 开头）：头部水平角超过 15° 且持续至少 0.2 秒算一次。回答"头实际转了几次、转了多少度"。
  - **人工标注的瞥视**（列名不带前缀）：3 位标注者在视频上标出的"往哪边看"的事件。回答"往哪边看了几次"，其中约一半只有很小的头部转动（以眼动为主）。
- **主要数字**（88 段平均）：算法检出左右转头 2.65 次/分，每次峰值约 28°、持续约 1.3 秒；人工标注的左右瞥视 3.4 次/分；
  算法检出的转头 93% 落在某次人工瞥视上；人工瞥视的方向与头部角度的方向一致率 96.3%；四种环境之间没有显著差异。
- **可信度**：水平角与一个独立信号逐段核对，相关平均 0.84，88 段全部可信，转头幅度准确（比值 0.97）。**俯仰角不可信，不要用于结论。**
- **必须知道的三点**：
  1. 关节点只覆盖每段驾驶的前约 77%，最后约 20% 没有数据（见 §7）。
  2. 人工标注的帧号是 24 fps，已换算为视频的 29.97 fps；2026-11-27 之前的结果因此是错位的，已归档，不要再用（见 §9）。
  3. 下游只使用主模型的结果（`fused_main/` 子目录），其他子目录是对照。

## 1. 这项分析回答什么问题

STEP1 统计**整段驾驶**中的头部运动：转头多不多、转多大、持续多久、朝哪边，以及这些量在不同环境之间、不同受试者之间是否不同。
它为"用头部运动补偿视野"的相关假说提供指标。按原有的对应关系：

- 转头**频率**：`ai_horizontal_turns_per_min`
- 转头**幅度**：`ai_horizontal_peak_deg_mean`、`yaw_p95_abs_deg`（以及人工瞥视期间的峰值角 `horizontal_event_peak_yaw_deg_mean`）

**尚未完成**：群组之间的比较（需要受试者分组或障碍程度表，拿到后按 `person` 列合并进主表即可检验），
以及 STEP2 的事件分析（红灯、急刹、掉头等时刻的注视对象，需要事件时刻表和各注视区域的方向表）。

## 3. 方法

### 3.1 头部角度

1. 在融合关节点的身体坐标系里（颈部为原点，肩线为左右轴，逐帧随躯干旋转），取"两耳中点 → 鼻尖"作为头部朝向。
2. 水平角 yaw = 朝向在左右方向上的偏转；俯仰角 pitch = 朝向的上下倾斜。
   **正负号：yaw 正 = 驾驶者的右侧，负 = 左侧；pitch 正 = 抬头，负 = 低头。**
3. 平滑：先做 5 帧中值滤波，再做 9 帧滑动平均（约 0.3 秒）。
4. 零点：减去该段驾驶期间的中位数，即以"平时看前方的方向"为 0°。

因为身体坐标系随躯干转动，`yaw_deg` 是**头相对躯干**的角度；`yaw_abs_deg` 是**头相对座舱**的角度，包含躯干转动。

### 3.2 算法检出的转头（`ai_` 列）

- 水平转头：|yaw| > 15° 且连续至少 6 帧（0.2 秒），中间断开不超过 3 帧的合并为一次。方向取这次转头峰值的正负号。
- 上下转头：|pitch| > 10°，其余相同。
- 只在驾驶区间内、有关键点的帧上检出；频率按**有关键点的时长**计算。

### 3.3 人工标注的瞥视事件

- 3 人中**至少 2 人**在同一帧标了左右类（含斜向），这些连续帧构成一次左右瞥视；中间断开不超过 2 帧的合并。上下同理。
- 斜向标签同时计入左右和上下。方向按多数决定。
- 标注者一致性：Fleiss κ，在驾驶区间内逐帧比较"标了 / 没标"。

### 3.4 两者的对照

| 指标 | 定义 |
|---|---|
| 重叠比例 | 算法检出的左右转头中，与某次人工左右瞥视在时间上重叠的比例 |
| 瞥视期间的峰值角 | 每次人工左右瞥视（前后各放宽 5 帧）内 \|yaw\| 的最大值 |
| 伴随 ≥15° 转头的比例 | 人工左右瞥视中，上述峰值角 ≥ 15° 的比例 |
| 逐段方向一致率（`sign_agreement_horizontal`） | 每段内，瞥视期间峰值角的正负号与标注方向一致的比例。所有瞥视都计入，包括头几乎没动的 |
| 方向一致率（`glance_direction_agreement.md`） | 每次左右瞥视期间 yaw 的**平均值**减去驾驶中位数，若偏离 ≥ 3° 则判定方向，统计判定方向与标注一致的比例，88 段合并计算。**报告方向一致率请用这个** |

### 3.5 环境比较的检验

按受试者配对：Friedman 检验比较 4 种环境；Wilcoxon 符号秩检验比较白天与夜间（各取两种环境的平均）、多い与少ない。

### 3.6 检出准确度

把不同阈值（水平 10–40°，上下 5–20°）和最短持续时间（3、6、9 帧）下检出的转头，与有关键点范围内的人工瞥视逐一配对，
汇总 88 段计算精确率、召回率和 F1。注意人工瞥视不是"头部转动"的标准答案，所以这里衡量的是两者的重合程度，不是算法的准确度。

## 6. 主要结果（`fused_main`，88 段）

### 6.1 测量可信度

与独立核对信号逐段比较（`python analysis/head_movement/source_validity.py`）：

| 关节点来源 | yaw 相关：平均 / 最低 | 失效段（相关 < 0.5） | 转头幅度比* | 静止时 yaw 噪声 | pitch 相关 | 瞥视方向一致率 |
|---|---|---|---|---|---|---|
| 单视角 front | 0.76 / 0.20 | 6 | 0.71 | 2.5° | 0.32 | 94.8% |
| 单视角 left | 0.83 / 0.51 | 0 | 0.84 | 2.8° | 0.38 | 94.9% |
| 单视角 right | 0.79 / 0.22 | 4 | 0.79 | 2.5° | 0.37 | 95.2% |
| 中位数融合 | 0.83 / 0.48 | 1 | 0.79 | 2.4° | 0.44 | 96.4% |
| 均值融合 | 0.85 / 0.52 | 0 | 0.78 | 2.2° | 0.45 | 96.5% |
| **主模型 `fused_main`** | **0.84 / 0.59** | **0** | **0.97** | 3.0° | 0.40 | 96.3% |

\* 核对信号显示转头超过 20° 的帧上，关节点 yaw 与核对信号之比的中位数；1 = 幅度一致。

- 单个摄像头在若干段上失效（方向盘和自身遮挡了耳朵）；融合后没有失效段。
- 主模型的优势在**幅度**：其他来源都把大幅转头低估 16–29%，主模型基本准确。因此它检出的转头更多（2.65 对均值融合 2.10 次/分）。
  静止时的逐帧噪声略大于均值融合。
- **俯仰角对所有来源都弱（相关 0.32–0.45），主模型也只有 0.40。** 所有上下方向的指标不要用于结论；算法检出的上下转头（5.7 次/分，均值融合为 1.4 次/分）明显被噪声抬高。

### 6.2 头部运动的量

| | 88 段平均 |
|---|---|
| 算法检出的左右转头 | 2.65 次/分（每段 0.27–6.38），左 5.2 次、右 6.7 次 |
| 每次转头的峰值角 | 28.1°（每段平均 17.7–36.4°） |
| 每次转头的持续时间 | 1.31 秒 |
| 头部 yaw 的 95 分位 | 16.6° |
| 人工左右瞥视（有关键点范围内） | 3.41 次/分，每次平均持续 2.7 秒（含上下） |

受试者之间差异很大，例如 01_昼多い 6.38 次/分（88 段中最高），17_夜少ない 1.39 次/分。

### 6.3 与人工瞥视的关系

- 算法检出的左右转头 **93%** 落在某次人工瞥视上：算法很少在没人标注的地方报出转头。
- 人工左右瞥视中只有 **约一半（0.50）** 伴随 ≥15° 的转头，瞥视期间的峰值 yaw 平均 20.1°：其余以眼动为主，头转得小。
- 方向：1692 次左右瞥视中 1412 次（83%）头部偏离 ≥3°，其中 **96.3%** 的方向与标注一致。
- 标注者之间：左右 κ = 0.72（相当一致），上下 κ = 0.40（较弱）。
- 按 15°、6 帧的检出规则与人工瞥视逐一配对：精确率 0.56、召回率 0.44、F1 0.49；最高 F1 为 0.55（10°、9 帧）。
  召回率低是因为一半瞥视没有明显转头，这是两种量本身的差异，不说明角度不准。

## 7. 使用时必须注意

1. **只覆盖每段驾驶的前约 77%。** SAM3D 推理的帧范围当初按未换算的标注帧号截取，所以每段最后约 20% 没有关键点。
   算法指标是"有数据部分"的频率；与人工标注比较时请用 `_in_covered_window` 列。补齐这部分需要重新推理。
2. **两种频率的分母不同。** `horizontal_turns_per_min` 按整段驾驶计算，`ai_horizontal_turns_per_min` 按有关键点的时长计算。
3. **瞥视不等于转头。** 人工标注反映"往哪边看"，约一半主要是眼动。研究头部的补偿动作，以算法检出的转头为主指标。
4. **方向一致率请引用 96.3%**（`glance_direction_agreement.md`），不要用主表的 `sign_agreement_horizontal`（0.85）——后者把头几乎没动、正负号接近随机的瞥视也计入。
5. **俯仰类指标不要用于结论**（所有 `vertical`、`pitch` 列）。
6. **`horizontal_event_peak_yaw_abs_deg_mean` 有异常大的值**（最大 110°），来自三角化参考，包含躯干转动，使用前逐段检查。
7. **核对信号只是部分独立。** 它来自同一个模型（SAM3D-Body）的另一个输出头，能排除鼻、耳遮挡带来的错误，但不是外部测量设备。
8. **4 种环境是同一批人重复测量**，统计时必须按人配对（本分析已这样做）。
9. **检出阈值是固定的**（15°、10°、0.2 秒），没有按任何结果调整；`detection_accuracy.csv` 只作参考，不要据此另选阈值后再报告结果。
